## Overview

Use Table for structured data arranged in rows and columns.

Tables are useful for invoices, users, orders, logs, permissions, metrics, and any data where users compare values across rows.

## Anatomy

A table has a caption or surrounding heading, header rows, body rows, cells, and an optional footer. `TableSectionHeader` can divide a long body into named row groups without abandoning table semantics.

## Usage guidance

Use tables for comparison. Use cards or lists when each item has varied content and users do not need column alignment. Keep numeric columns aligned, format values consistently, and let the built-in container scroll horizontally instead of compressing content beyond recognition.

## Accessibility

Add a concise caption or associate the table with a visible heading. Set `scope="col"` on column headers and `scope="row"` on row headers; use `scope="colgroup"` for a section header. Keep row actions clearly labeled, and do not make an entire row clickable unless the same destination is exposed as a real link.

## Usage

```tsx
import {
  Table,
  TableBody,
  TableCaption,
  TableCell,
  TableFooter,
  TableHead,
  TableHeader,
  TableRow,
  TableSectionHeader,
} from "@/components/ui/table";
```

```tsx
<Table>
  <TableCaption>Caption</TableCaption>
  <TableHeader>
    <TableRow>
      <TableHead>Header</TableHead>
      <TableHead>Header</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>Cell</TableCell>
      <TableCell>Cell</TableCell>
    </TableRow>
  </TableBody>
</Table>
```

## API reference

All Table parts accept props for their matching native HTML elements. `TableRow` adds `interactive?: boolean` for hover and active styling; it does not add click behavior. `Table` wraps the native table in a horizontally scrollable container. `TableSectionHeader` renders a `tr`, so place one or more `TableHead` cells inside it.
