## Overview

Use Skeleton to reserve space while content is loading.

Skeletons are useful for cards, tables, lists, avatars, charts, and forms where the layout is known before the data arrives.

## Anatomy

A skeleton is a neutral placeholder shape. It should roughly match the size and rhythm of the content that will replace it.

## Usage guidance

Use skeletons for short loading states where preserving layout helps. Avoid showing too many animated placeholders at once.

## Accessibility

Do not announce every skeleton as content. Pair long loading states with clear loading text when users need to understand what is happening.

## Decision guidance

Match skeleton shapes to the stable layout, but do not reproduce every line of the final content. Keep the loading region's size steady to avoid layout shift. For fast operations, delay the visual skeleton briefly so it does not flash; for long operations, add plain language that says what is loading.

## API reference

`Skeleton` accepts native `div` props and has no accessible name by default. Mark decorative shapes with `aria-hidden="true"`, put `aria-busy="true"` on a containing region when you can track the shared loading state, and provide a status message when loading is not otherwise clear. Replace the skeleton with real content rather than placing content inside it.
