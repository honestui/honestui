## Overview

Use a card to group related content and actions inside a clear surface.

Cards work well for dashboards, settings groups, pricing items, summaries, and repeated list items. Avoid nesting cards inside cards unless each layer has a clear job.

## Anatomy

A card usually has a container, header, title, description, panel, footer, and optional action. `CardAction` shares the header grid with the title and description. Not every card needs every part; omit empty regions instead of preserving a template shape.

## Usage guidance

Use cards for repeated items or self-contained content groups. For broad page sections, prefer normal page layout instead of turning every section into a card. The four visual variants change emphasis, not meaning, so choose one hierarchy and use it consistently.

## Accessibility

Use real headings when the card introduces a section; `CardTitle` is a `div`, so compose or wrap it with the appropriate heading level. Avoid nested interactive targets. If the whole card leads somewhere, use one real link with a clear label instead of a click handler on the container.

## Usage

```tsx
import {
  Card,
  CardAction,
  CardDescription,
  CardFooter,
  CardHeader,
  CardPanel,
  CardTitle,
} from "@/components/ui/card";
```

```tsx
<Card>
  <CardHeader>
    <CardTitle>Storage</CardTitle>
    <CardDescription>8.4 GB of 20 GB used</CardDescription>
  </CardHeader>
  <CardPanel>Review the files using the most space.</CardPanel>
  <CardFooter>Manage storage</CardFooter>
</Card>
```

## API reference

`Card` accepts native `div` props and a `variant` of `default`, `soft`, `mixed`, or `outline`. `CardHeader`, `CardTitle`, `CardDescription`, `CardAction`, `CardPanel`, and `CardFooter` accept native `div` props. `CardContent` is an alias of `CardPanel` for compatibility.
