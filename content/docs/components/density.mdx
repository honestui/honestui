## Control sizes

Use `sm`, `default`, or `lg` to match buttons, text fields, selects, number controls, and toggles in the same row. Density sets the default size for a section; explicit sizes remain available for individual controls.

<ComponentPreview name="control-size-comparison" previewClassName="h-auto sm:h-auto" />

## Overview

A density scope sets the size of controls, menu items, table rows, and gaps for everything inside one element. You mark the section once instead of passing a size to every component in it.

There are three levels: `compact`, `default`, and `comfortable`. `default` is what controls use outside any scope: 36px, with 28px small and 44px large controls. `compact` is 28px and `comfortable` is 40px.

## Anatomy

Density has two parts. The `honestui/density.css` stylesheet defines the variables for each level on `[data-density]` and adds three Tailwind variants. `DensityScope` renders the element that carries `data-density` and shares the level through React context, which is how portaled popups and `DataGrid` receive it. `DensityProvider` shares a level without rendering an element, and `useDensity` reads it.

## Accessibility

Density changes size only. Roles, names, focus order, focus rings, and font sizes are the same at every level.

### Touch behavior

On devices whose primary pointer is coarse (`@media (pointer: coarse)`), every scope gives controls, menu items, and table rows a minimum height of 44px. Padding and gaps keep their level.

Compact rows are stacked edge to edge, so an invisible 44px hit area on a 28px control would overlap the row above and below. A real 44px box avoids that. The floor applies to all three levels so that compact is never larger than default on the same screen.

Two things to know:

- Outside a scope, components keep their existing touch behavior. Set a scope on your app root if you want the 44px floor everywhere.
- Explicit `sm` and `lg` sizes follow the level too: `sm`, `default`, and `lg` controls are 24, 28, and 36px in `compact`, 28, 36, and 44px in `default`, and 32, 40, and 48px in `comfortable`. On touch, a scope raises `sm` and `default` controls to 44px and `lg` controls to 48px.

Change the floor by setting `--hui-density-touch-target` on `:root` or on a scope.

## Installation

`honestui/theme.css` includes the density variables, so controls outside a scope use the `default` level. Set `data-density` to change a section.

Import `honestui/density.css` in your Tailwind stylesheet for the `density-*` variants, or when you load the Honest UI tokens without `honestui/theme.css`. Import it after Tailwind CSS and the tokens; it uses the [spacing tokens](/docs/theme/spacing).

```css
@import "tailwindcss";
@import "honestui/density.css";
```

Add `DensityScope` to your project. `Menu`, `Select`, `DataTable`, and `DataGrid` import it, so the CLI installs it with them.

## Usage

Use `DensityScope` for a section:

```tsx
import { DensityScope } from "@/components/ui/density"

export function InvoicesPanel() {
  return (
    <DensityScope density="compact">
      <InvoiceToolbar />
      <InvoiceTable />
    </DensityScope>
  )
}
```

`DensityScope` renders a `div` with `data-density` and accepts any `div` prop.

A bare attribute also works when the section has no popups, `DataTable`, or `DataGrid`:

```tsx
<section data-density="compact">…</section>
```

Menus and select lists are portaled to the end of the document, outside the section's DOM subtree, so CSS inheritance cannot reach them. They read the density from `DensityScope` instead. `DataTable` and `DataGrid` read it there too: they resolve their density in React, and `DataGrid` needs the row height in JavaScript for virtualization.

### Read the density in a component

`useDensity()` returns the density of the nearest `DensityScope`, or `undefined` outside one. It does not see a bare `data-density` attribute.

```tsx
import { useDensity } from "@/components/ui/density"

function RowAvatar() {
  const density = useDensity()
  return density === "compact" ? null : <Avatar />
}
```

Use `DensityProvider` to share a density without rendering an element, for example when your own component already renders the element that carries `data-density`.

## Components that follow density

| Component | What changes |
| --- | --- |
| `Button` | Height and padding of the default size; width and height of `size="icon"` |
| `Input` | Height of the default size |
| `Select` | Trigger height and padding of the default size; item padding |
| `Menu` | Item padding |
| `Table` | Cell and header padding |
| `Toolbar` | Gap and padding |
| `DataTable` | Row padding; `density` prop now also accepts `comfortable` |
| `DataGrid` | Row height (44px, 56px, or 64px) |

`DataTable` and `DataGrid` use their `density` prop when it is set and inherit from `DensityScope` when it is not. Either way they become a scope for the buttons, inputs, and menus inside them.

## Tailwind variants

The stylesheet adds three Tailwind CSS v4 variants for changes a variable cannot express, such as hiding secondary text in compact sections:

```tsx
<p className="density-compact:hidden">Last synced 2 minutes ago</p>
<Avatar className="size-8 density-compact:size-6 density-comfortable:size-10" />
```

`density-compact:`, `density-default:`, and `density-comfortable:` match the scope element and the elements whose nearest scope has that level.

One limit: when a level is re-entered through a different level, such as compact inside comfortable inside compact, the variant does not match in the innermost scope. The variables have no such limit, so prefer them for sizing.

## API reference

### DensityScope

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `density` | `"compact" \| "default" \| "comfortable"` | Required | The density for this section. |
| `...props` | `React.ComponentProps<"div">` | — | Passed to the rendered `div`. |

### DensityProvider

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `density` | `"compact" \| "default" \| "comfortable"` | Required | The density shared with descendants. |
