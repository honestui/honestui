Honest UI charts are composable React chart components built on <Link href="https://echarts.apache.org/" _blank={true}>Apache ECharts</Link>. Install them from `honestui/charts`, then compose the axes, series, legend, tooltip, and controls your visualization needs.

Charts are package imports rather than CLI-copied UI components. You can inspect their source in the Honest UI repository and use ECharts options when the component API does not expose a setting directly.

## Choose a chart

| Chart | Use it to | Use something else when |
| --- | --- | --- |
| [Area chart](/docs/charts/area-chart/static) | Show change over time when magnitude or contribution to a total matters | A filled area would make close comparisons harder |
| [Bar chart](/docs/charts/bar-chart/static) | Compare values across categories | The primary question is change over a continuous sequence |
| [Line chart](/docs/charts/line-chart/static) | Show trends and rate of change across an ordered dimension | The data is unordered or category comparison matters more |
| [Pie or donut chart](/docs/charts/pie-chart/static) | Show a simple part-to-whole relationship with a few categories | Values are close, there are many categories, or precision matters |
| [Scatter chart](/docs/charts/scatter-chart/static) | Find relationships, clusters, and outliers across numeric measures | One axis is categorical |
| [Heatmap](/docs/charts/heatmap/static) | Find patterns across two categorical dimensions | Readers need frequent point-by-point comparison |
| [Combo chart](/docs/charts/combo-chart/static) | Plot an amount as bars and a related rate or trend as a line on one category axis | Both measures share a unit, so a grouped bar or multi-line chart is simpler |
| [Waterfall chart](/docs/charts/waterfall-chart/static) | Explain how increases and decreases move a starting value to an ending value | The steps have no order or do not add up to a total |
| [Candlestick chart](/docs/charts/candlestick-chart/static) | Show open, high, low, and close values for each period | Only the closing value matters, so a line is clearer |
| [Radar chart](/docs/charts/radar-chart/static) | Compare the overall profile of a few series across measures on one scale | Readers need exact values or measures use different units |
| [Radial chart](/docs/charts/radial-chart/static) | Show progress toward a goal for a few categories as rings | Categories need precise comparison, which bars do better |
| [Gauge chart](/docs/charts/gauge-chart/static) | Show one value against a min, max, and qualitative ranges | Several values need comparing, or the trend matters more than the latest value |
| [Bullet chart](/docs/charts/bullet-chart/static) | Compare a measure to a target and performance ranges in little space | There is no target or range to compare against |
| [Funnel chart](/docs/charts/funnel-chart/static) | Find where people or items drop out of an ordered sequence of stages | Stages are not subsets of the previous stage |
| [Sankey chart](/docs/charts/sankey-chart/static) | Show how quantities flow and split between stages or categories | There are many small flows or cycles |
| [Treemap](/docs/charts/treemap/static) | Show part-to-whole relationships across a hierarchy | Values are close in size or exact comparison matters |
| [Contribution graph](/docs/charts/contribution-graph/static) | Show daily activity over months as a calendar heatmap | The data is not daily or the exact trend matters more than the pattern |
| [Sparkline](/docs/charts/sparkline/static) | Show a trend inline beside a number, in a table or a stat card | Readers need axes, labels, or exact values |
| [Bar list](/docs/charts/bar-list/static) | Rank labeled items by value, such as top pages or referrers | Values change over time and the trend matters |
| [Tracker](/docs/charts/tracker/static) | Show a history of discrete states, such as uptime per day | The measure is continuous, such as latency |
| [Category bar](/docs/charts/category-bar/static) | Show where a value falls within ranges, or a split of one total | There are many segments or the segments do not add up to one whole |

## How composition works

The chart root owns the data, theme configuration, loading state, and selection. Add only the parts you need. For example:

```tsx
<BarChart data={data} config={chartConfig}>
  <BarChart.Grid />
  <BarChart.XAxis dataKey="month" />
  <BarChart.Legend />
  <BarChart.Tooltip />
  <BarChart.Bar dataKey="completed" />
</BarChart>
```

The child components describe ECharts configuration; they do not render separate DOM elements. Omitting a child removes that chart part. Use [Chart Config](/docs/charts/chart-config) to connect data keys to visible labels, colors, and optional icons.

## Canvas and performance

ECharts renders the plot to canvas, avoiding one DOM element for every bar, point, or cell. That can reduce DOM size for dense visualizations, but performance still depends on the dataset, enabled interactions, animation, device, and surrounding application. Test representative data on the devices your product supports.

## Accessibility responsibilities

A canvas can have an accessible name, but that name does not expose every plotted value or relationship. Provide a nearby summary or data table when people need to understand exact values, trends, outliers, or selections.

Tooltips, brushes, and direct mark selection are pointer-operated unless your application supplies an equivalent control. Do not place required information or the only path to an action inside a canvas interaction.

## Get started

Follow [Installation](/docs/charts/installation), define labels and colors in [Chart Config](/docs/charts/chart-config), and choose a chart based on the question the data must answer.
